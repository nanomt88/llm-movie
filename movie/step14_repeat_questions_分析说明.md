## 一、分析背景与问题

本步骤独立于主流水线 12 步之外，聚焦于**用户重复提问行为**的特征分析。在
Reddit 电影推荐会话数据集中，用户可以跨多个会话、多个轮次提问。了解用户
"重复提问"的模式，有助于回答以下问题：

1. 有多少比例的用户会反复提问？这反映了用户的活跃粘性和需求深度。
2. 重复提问的用户平均提多少个问题？提问有多长？这刻画了高活跃用户的行为画像。
3. 提问次数的分布如何？是否存在极端活跃的"超级用户"？
4. 提问内容的长度分布如何？用户提问是简短关键词式还是详细描述式？
5. 重复提问用户平均涉及多少个会话？每个会话平均提多少个问题？这揭示了用户的
   交互模式——是"单会话多问"还是"跨会话追问"。
6. 不同提问频率的用户，其会话数量分布如何？高频提问者是否也跨更多会话？

### 1.1 重复提问的定义

> **重复提问用户**：同一用户在去重后（排除完全相同的冗余记录后）提出了 **≥2 条**
> 不同提问（内容或时间不同）的用户。

去重采用两层逻辑，严格遵循项目数据规则（AGENTS.md 规则9）：

| 层次 | 去重键 | 说明 |
|---|---|---|
| 第一层：会话内去重 | `(session_id, proc_text)` | 同一会话内相同文本的提问只保留首条（规则9） |
| 第二层：跨会话精确去重 | `(user_id, proc_text, utc_time)` | 同一用户、同一文本、同一时间戳的记录视为数据冗余，只保留首条 |

**"内容与时间均不同"的含义**：两层去重后，每条留存的提问记录都由
`(proc_text, utc_time)` 唯一标识。只有当**内容和时间戳均相同**时才视为冗余并
剔除；若内容相同但时间不同（用户在不同时刻重复了同一问题），则视为两条独立
提问，计入重复提问次数。

## 二、数据分析思路

### 2.1 统计口径

| 维度 | 口径 | 说明 |
|---|---|---|
| **分析语料** | 用户提问行（`is_seeker=True`） | 仅分析用户侧提问，不含系统回复 |
| **分析单位** | 用户级（`user_id`） | 以唯一用户为基本单位统计 |
| **数据范围** | 2019–2022 全量数据（经 `load_all()` 过滤） | 排除 2018 年及 2019-01-01 人工采集产物 |
| **去重策略** | 两层去重（会话内 + 跨会话精确） | 见上表 |
| **提问长度** | `len(proc_text)` 字符数 | proc_text 为已处理文本（电影名已替换为 tt ID） |
| **重复提问用户** | 去重后提问数 ≥ 2 的用户 | 核心统计对象 |

### 2.3 统计及计算步骤

#### 步骤 1：数据加载

```python
data = load_all()
seekers = data['seekers']  # 721,490 条用户提问
```

#### 步骤 2：两层去重，按用户收集提问

```python
# 第一层：会话内去重（规则9）
deduped = deduplicate_seekers(seekers)  # 721,490 → 146,768

# 第二层：按用户分组，跨会话精确去重 (proc_text, utc_time)
user_unique = _collect_user_questions(deduped)  # 35,581 用户, 146,334 提问
```

#### 步骤 3：维度1–6 计算

- **维度1**：统计 `len(qs) >= 2` 的用户数，计算占比
- **维度2**：对重复用户求 `mean(提问数)` 和 `mean(len(proc_text))`
- **维度3**：对重复用户的提问次数分 6 档统计分布
- **维度4**：对重复用户的所有提问按长度分 6 档统计分布
- **维度5**：对重复用户按 `session_id` 二次分组，计算每用户会话数与每会话提问数
- **维度6**：将重复用户按提问次数分 4 组（保障均匀），统计每组内会话数分布

#### 分组策略（参考实际数据，避免严重倾斜）

**维度3 提问次数分组**（基于实际分位数 p50=4, p75=7, p90=12, p95=18）：

| 分组 | 范围 | 依据 |
|---|---|---|
| 2 | 恰好2条 | 最低重复门槛，单独观察 |
| 3-4 | 3~4条 | p50 附近 |
| 5-10 | 5~10条 | p50–p90 之间 |
| 11-20 | 11~20条 | p90–p95 |
| 21-50 | 21~50条 | p95–p99 |
| 50+ | 50条以上 | 极端活跃用户 |

**维度4 提问长度分组**（基于实际分位数 p25=43, p50=97, p75=238, p90=448）：

| 分组 | 范围 | 含义 |
|---|---|---|
| 0-30 | 极短 | 关键词式提问（如 "horror movie?"） |
| 31-80 | 短 | 简短提问 |
| 81-150 | 中等 | 标准提问 |
| 151-300 | 长 | 详细描述 |
| 301-500 | 很长 | 非常详细 |
| 500+ | 极长 | 长篇描述 |

**维度5 会话统计**（无需分组，直接计算均值/中位数）：
- 每用户会话数 = 同一 `user_id` 下不同 `session_id` 的数量
- 每会话提问数 = 该用户在该 `session_id` 下去重后的提问条数

**维度6 提问次数分组**（保障均匀分布，合并尾部避免倾斜）：

基于维度3 的实际分布（30%/30%/27%/9%/3%/0.8%），将尾部 3 档合并为 1 档，
形成 4 组均衡分布：

| 分组 | 范围 | 占比 | 依据 |
|---|---|---|---|
| 2 questions | 恰好2条 | 30.30% | 最低重复门槛 |
| 3-4 questions | 3~4条 | 30.03% | p50 附近 |
| 5-10 questions | 5~10条 | 26.78% | p50–p90 |
| 11+ questions | 11条以上 | 12.88% | 合并 11-20+21-50+50+，保障最小组 ≥10% |

**会话数分箱**（维度6 组内分布）：

| 分箱 | 范围 | 含义 |
|---|---|---|
| 1 session | 1个会话 | 单会话用户 |
| 2 sessions | 2个会话 | 轻度跨会话 |
| 3-5 sessions | 3~5个会话 | 中度跨会话 |
| 6-10 sessions | 6~10个会话 | 高度跨会话 |
| 11+ sessions | 11个以上 | 极端跨会话用户 |

## 四、解释与结论

1. **重复提问是主流行为**：58.31% 的用户在 4 年内提出多个不同问题。这
   说明电影推荐系统是用户**反复使用**的工具，而非一次性查询。高复用率
   支撑了推荐系统的持续价值。

2. **重复用户是提问量的主体**：20,746 名重复用户（占 58.31%）贡献了
   89.9% 的提问量。少数单次用户（41.69%）仅贡献 10.1%。如果需要优化
   推荐体验，应重点服务重复用户群体。

3. **提问次数分布呈典型长尾**：60% 的重复用户提问 2–4 次（普通活跃），
   但存在 156 名极端活跃用户（50+ 次，最多 1,083 次）。这种长尾分布是
   社区型平台的典型特征——少量核心用户贡献大量内容。

4. **提问长度双峰分布**：用户要么简短直问（44%，0–80 字符），要么详细
   描述（38%，151+ 字符）。中等长度的"标准提问"反而是少数（18%）。
   这暗示两类用户需求：
   - **效率型**：知道想要什么，用关键词快速提问
   - **探索型**：需求复杂，需要详细描述偏好和场景

5. **重复用户的单条提问更短**：重复用户平均长度 193 < 全部用户 210。
   原因是重复用户倾向于"多轮短问"（来回追问细化需求），而单次用户倾向
   于"一轮长问"（一次描述完所有需求）。这反映了两种不同的交互策略。

6. **会话内去重率极高（79.7%）**：同一会话内大量轮次重复同一文本。
   这既有用户行为因素（在等待系统回复时重发问题），也可能有数据采集
   因素。按规则9去重后，有效数据量从 72 万降至 15 万条。

7. **"单会话多问"是主流交互模式**：重复用户平均 2.05 个会话但中位数仅 1，
   超过一半的重复用户在单会话内完成所有提问。每会话平均 3.09 条提问
   说明用户在同一对话中来回追问 3 轮左右。推荐系统应优化会话内的多轮
   交互体验，而非鼓励跨会话回访。

8. **提问频率与会话数正相关但非线性**：低频用户（2 次提问）几乎全在
   单会话内完成（75.7%），高频用户（11+ 次）平均 5.34 个会话。但即使
   最高频组仍有 29% 在单会话内完成所有提问——高频提问不等于跨会话。
   存在两类极端用户：密集追问型（单会话内提大量问题）和长期回访型
   （跨多个会话持续提问）。

## 五、方法学回顾与局限

| 设计点 | 实现情况 | 评估 |
|---|---|---|
| 两层去重（会话内 + 跨会话精确） | ✅ | 会话内按规则9去重，跨会话按(user,text,time)去重 |
| 用户级分析单位 | ✅ | 以 user_id 为唯一标识 |
| proc_text 作为长度度量 | ✅ | 标准化文本，电影名替换为 tt ID |
| 维度3/4 分组参考实际分位数 | ✅ | 6 档分布占比 0.75%–30%，无严重倾斜 |
| 维度6 分组保障均匀分布 | ✅ | 4 组占比 13%–30%，最小组 ≥10%，合并尾部避免倾斜 |
| 会话级二次分组（维度5/6） | ✅ | 基于去重后的提问按 session_id 二次分组 |
| 同时输出均值与中位数 | ✅ | 应对右偏分布，中位数更有代表性 |

**局限**：

1. **proc_text 长度不等于原始提问长度**：电影名已被替换为 tt ID
   （如 "Inception" → "tt1375666"），长度可能有偏差。但作为标准化度量，
   用于分组比较是合理的。
2. **未区分"内容相同时间不同"与"内容不同"的重复**：当前将同一文本
   不同时间的提问也计入重复次数。若需区分"同问题重发"与"不同问题
   追问"，需进一步细化。
3. **未按时间维度分析**：当前是全量汇总，未分析重复提问行为随年份/
   节假日的变化趋势。
4. **未结合系统回复分析**：仅分析了用户侧，未涉及重复提问是否得到了
   更好/不同的推荐。
5. **极端值影响**：最大提问数 1,083、最大长度 22,040 可能包含自动化
   行为或数据异常，未做异常值剔除。
6. **user_id 可靠性**：Reddit 的 user_id 在数据中是唯一标识，但同一
   真人可能有多个账号，或存在共享账号，分析以数据中的 user_id 为准。
